## Why Velite?

[Velite](https://velite.js.org) is the spiritual successor to Contentlayer — it transforms local markdown/MDX files into fully typed TypeScript objects at build time.

No external database, no CMS costs, just files in your repo.

## Schema Definition

```ts
// velite.config.ts
const posts = defineCollection({
  name: "Post",
  pattern: "posts/**/*.mdx",
  schema: s.object({
    title: s.string(),
    date: s.isodate(),
    tags: s.array(s.string()).default([]),
    body: s.mdx(),
  }),
});
```

Velite validates every frontmatter field against the Zod-compatible `s` schema and **fails the build** if something is wrong — no silent data bugs at runtime.

## Syntax Highlighting

I'm using `rehype-pretty-code` backed by [Shiki](https://shiki.matsu.io), which renders code blocks as plain HTML — no client-side JavaScript needed.

```python
def hello(name: str) -> str:
    return f"Hello, {name}!"

print(hello("world"))
```

Themes are set per-appearance:

```ts
rehypePrettyCode({ theme: { dark: "github-dark-dimmed", light: "github-light" } })
```

## The Final Workflow

1. Write a `.mdx` file in `content/posts/`
2. Run `next build` (Velite runs first via the custom webpack plugin)
3. The typed `posts` array is available anywhere in the app

That's it — no CMS dashboard, no API calls, no cold starts.
