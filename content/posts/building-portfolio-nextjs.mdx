## Why I Built My Own Portfolio

After years of using third-party portfolio builders and generic website templates, I decided to roll my own custom platform from scratch. 

### The Need for Complete Independence

Commercial portfolio platforms often lock you into rigid layouts, introduce tracking scripts that hurt performance, and restrict how you present interactive demos. By owning the codebase:

- **Zero recurring fees** — Deployed globally on Vercel's edge network for free.
- **Tailored UX** — Custom keyboard shortcuts, smooth scrollspies, and a floating dock inspired by macOS and iOS.
- **Dog-fooding modern tech** — Practical testing ground for Next.js 16, React Server Components, and Tailwind CSS v4.

### Next.js 16 App Router & Server Components

The entire application leverages React Server Components (RSC) by default. Dynamic interactivity — such as the floating dock, theme switcher, and copy-code buttons — are isolated into tiny, zero-waterfall client boundaries.

<Callout type="warning" title="Turbopack Windows Path Gotcha">
When configuring alias paths like `@velite` with Next.js 16 and Turbopack on Windows, always use relative path strings (`"./.velite"`) in `turbopack.resolveAlias` instead of `path.resolve(__dirname, ...)`.
</Callout>

```tsx
// src/app/blog/[slug]/page.tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  const post = posts.find((p) => p.slugPath === slug);
  if (!post) return {};

  return {
    title: `${post.title} | Blog`,
    description: post.description,
    openGraph: {
      title: post.title,
      type: "article",
      publishedTime: post.date,
    },
  };
}
```

### The Velite Content Layer

Instead of heavy CMS systems or runtime MDX compilation, I chose [Velite](https://velite.js.org/). Velite validates markdown content with Zod schemas at build time, generates TypeScript definitions, and outputs lightweight pre-compiled function strings:

```ts
// velite.config.ts
import { defineConfig, defineCollection, s } from "velite";

const posts = defineCollection({
  name: "Post",
  pattern: "posts/**/*.mdx",
  schema: s.object({
    title: s.string().max(99),
    date: s.isodate(),
    tags: s.array(s.string()).default([]),
    body: s.mdx(),
  }),
});
```

### Tailwind CSS v4 & Styling Pipeline

With Tailwind CSS v4's new Oxide engine, compilation is up to 10x faster and configurations reside cleanly in pure CSS without requiring a bloated `tailwind.config.js`.

| Framework / Tool | Purpose | Advantage |
| :--- | :--- | :--- |
| **Next.js 16** | Core Application Framework | Streaming SSR, Turbopack, App Router |
| **Tailwind v4** | Modern Utility CSS | Zero-config CSS variables, sub-millisecond HMR |
| **Velite** | Type-Safe Content Engine | Build-time Zod validation, automatic TOC |
| **Shiki** | Syntax Highlighting | Dual-theme light/dark token coloring |
| **Lucide** | Icon System | Crisp SVGs bundled offline with zero layout shift |

## Key Takeaways & What's Next

Building this project reaffirmed a few core principles:

1. **Keep dependencies lean**: Fewer client libraries means faster initial paint and lower battery consumption on mobile.
2. **Design for content first**: Typography, readable line-lengths (max 65–75 characters), and clear heading hierarchies make technical writing enjoyable.
3. **Automate everything**: From dynamic OpenGraph card generation to RSS feed synthesis and XML sitemaps, nothing requires manual maintenance.
